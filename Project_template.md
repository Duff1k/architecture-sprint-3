# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут включать и выключать отопление удалённо

- Пользователи могут устанавливать целевую температуру для своего дома

- Пользователи могут получать информацию о текущем состоянии системы отопления (включена/выключена, заданная температура)

- Пользователи могут обновлять параметры отопления

- Система поддерживает обработку HTTP-запросов от клиентов через REST API

- Система поддерживает сохранение и обновление состояния отопительной системы в базе данных

- Система поддерживает бизнес-логику управления отоплением: включение, выключение и установка температуры

- Система поддерживает сохранение состояния системы отопления между перезапусками сервера

- Система поддерживает централизованное логирование действий пользователя


**Мониторинг температуры:**

- Пользователи могут запрашивать текущую температуру в доме через веб-клиент

- Пользователи могут просматривать текущую температуру в рамках данных, доступных через API

- Система поддерживает получение текущей температуры от связанных сенсоров

- Система поддерживает хранение последнего известного значения температуры в базе данныхх

- Система поддерживает обновление информации о температуре вручную или по запросу со стороны сервера

### 2. Анализ архитектуры монолитного приложения

- Язык программирования Java, в данном решение используется фреймворк Spring Boot
- Сборка maven
- Используется БД PostgreSQL для работы с ним Spring Starter JPA и PostgreSQL драйвер
- В данном решении выбрана самая распространенная для монолитных приложений на Spring Boot слоистая архитектура с разделениями на (controller, service, entity/dto)
- Миграции БД нет, но подготовлен init.sql

### 3. Определение доменов и границы контекстов текущего решения

**Домены:**
- Управление отоплением
- Мониторинг температуры

**Контексты:**
- Heating Control Context (Управление включением, выключением, установкой температуры.)
- Temperature Monitoring Context (Сбор, хранение, предоставление температуры.)

### **4. Проблемы монолитного решения**

- Управление отоплением и сбор температуры неразделимы в коде и хранятся в одной модели
- Трудности масштабирования — невозможно независимо масштабировать, например, сбор телеметрии, если он станет высоконагруженным.
- Добавление новых модулей приведёт к разрастанию монолита.
- Одна ошибка или изменение в бизнес-логике отопления может затронуть мониторинг или другие части.
